## Why the FTP server is a small read-only implementation

Upstream ftpsrv is a general filesystem server. It includes upload/delete/rename, mount-related custom commands, SELF-to-ELF conversion, and standalone process management. Those are not needed for save backup. This fork adapts the passive connection design but implements a narrowly scoped server that only lists and retrieves the current save. It does not copy upstream's standalone main function, kill other FTP processes, or perform executable conversion.

Changes to adapted FTP logic, made 13 October 2026: OS-assigned ports; peer matching; one data connection per passive listener; initialized address lengths; bounded commands; socket timeouts; cleanup on all session exits; mount lock; restricted filesystem roots; TYPE I enforcement before RETR; explicit failures for unsafe paths or unsupported file types. Copyright and GPL notices are retained in batch_ftp.c. The complete ftpsrv snapshot makes the provenance reviewable.

## What the primary sources establish, and our resulting choices

- **Use the correct SDK and loader ABI.** The [SDK README](https://github.com/ps5-payload-dev/sdk/blob/f5d40f02770e9b0001dd9e18056eca70b3da8b40/README.md) describes this dynamic-linking payload SDK and known compatible loaders. We use its CRT, headers, stubs and linker script, with x86_64-sie-ps5, PIE, and 0x4000 maximum page alignment. We do not mix its ABI with the different PS5Dev/PS5SDK entrypoint conventions.
- **Loader persistence is not payload persistence.** The [elfldr README](https://github.com/ps5-payload-dev/elfldr/blob/02cfe91eb3f9697787460ad77d73ff951f801f50/README.md) describes independently spawned payload processes and the background loader. Our app sends its ELF to the running loader; it neither installs nor updates elfldr. A loader surviving a payload crash does not guarantee that a save mount survives safely.
- **FTP control and data are separate.** See [ftpsrv PASV/RETR](https://github.com/ps5-payload-dev/ftpsrv/blob/23737c4738d15b9b9b036665bbf008d8fd6d82d2/cmd.c) and [RFC 959](https://www.rfc-editor.org/rfc/rfc959). Mounter remains on 9090; the embedded FTP listener binds port 0 to request an available port. GET_CAPS reports the chosen port to the PC. Each passive data connection gets another available port. This avoids a second fixed payload port, but does not mean all traffic uses 9090. There is no universal registry that can guarantee a fixed port never conflicts with every community payload.
- **Binary means unchanged bytes.** Upstream RETR's ordinary file path copies raw bytes. Our server requires TYPE I for RETR, uses read/send loops, handles partial writes, and performs no CR/LF or SELF transformations. The PC sets UseBinary=true and checks lengths and local SHA-256 receipts. Hashes are not a remote-console checksum or a restore validation.
- **Lifetime and resource cleanup matter.** [ftpsrv release notes](https://github.com/ps5-payload-dev/ftpsrv/releases) discuss passive connection and file-descriptor fixes. Our passive sockets are single-use, data sockets are closed, command lines are bounded, and SIGPIPE is ignored. The mount mutex prevents unmount while LIST/RETR is reading. Data operations time out; cancellation can wait for that timeout. Process exit closes worker sockets. Force-kills/power loss remain outside orderly cleanup.
- **Enumerate profiles, not only login sessions.** Inspection of upstream mounter main.c showed GET_USERS uses GetLoginUserIdList. Our modified command unions that list with valid hexadecimal directories in /user/home, checks they are directories, and retrieves names when available. A fallback local-user label is used when the name lookup fails. The user subsequently confirmed their second profile is visible on the real console.
- **Firmware testing is explicit.** The user subsequently tested the combined payload provisionally labelled 0.2.0 on their PS5 Pro / firmware 13.60, confirmed both profiles, and completed a 442-save batch. Current development iteration 0.1.0-dev.5 changes the UI, backup naming and title lookup; native payload behavior is unchanged apart from the build label and output filename. Each revision's verification is documented in VALIDATION.md.

## Build and source availability

Process-name fix, 14 October 2026: inspection of the original ElfldrClient.cs confirms that it sends raw ELF bytes without a filename. elfldr socksrv.c assigns raw uploads the default name payload.elf, and elfldr.c sets that process name. Our payload now invokes syscall(SYS_thr_set_name, -1, "savemounter.elf") at startup, following the process-naming API usage in elfldr socksrv.c and ftpsrv main-prospero.c. A naming failure is logged without interrupting save services. No loader or transfer protocol change is required. This fixes the process label after startup; an already-running older payload must be stopped and the updated payload deployed before its label can change.

Windows payload build: use SDK v0.44 and LLVM 18.1.8 with build-payload.ps1. POSIX: export PS5_PAYLOAD_SDK and run make -C mounter_payload. The SDK release zip is available at https://github.com/ps5-payload-dev/sdk/releases/tag/v0.44. The .NET executable is built with build.ps1. Package savemounter.elf beside the EXE; protocol BATCH/2 is required. Build 0.1.0-dev.5 remains protocol-compatible with the previously labelled 0.2.0 combined payload.

## Online game title facts

PS4 source reviewed 14 October 2026: the official https://shadps4.net/compatibility/ page's CompatibilityPage JavaScript calls /scripts/search.php with q, status, version, os, region and page filters. Its JSON returns games objects with code and title. An exact public CUSA03173 query returned Bloodborne and three OS reports; our parser accepts only an exact code match and uses the title fact, not compatibility text or artwork. The GitHub compatibility workflow's compatibility_data.json contains status/version/issue metadata without title names, so it is not used as a name database. The page's unfiltered endpoint is paginated (154 pages at review time); our app queries only CUSA entries still lacking usable internal names instead of fetching every page. Requests disclose those missing CUSA IDs to shadPS4 when online lookup is enabled, but no console address, user/save names or file contents. No emulator/site code or artwork is incorporated. The site's footer reserves rights; this implementation independently consumes factual names/IDs at runtime and does not redistribute their website or a bundled database. Cache, limits, outage behavior and source attribution are documented in ADVANCED.md. The source website and official compatibility-report repository are credited in the GUI and here: https://github.com/shadps4-compatibility/shadps4-game-compatibility.

Updated 14 October 2026: [blackbearreloaded/ps5-homebrew-catalog](https://github.com/blackbearreloaded/ps5-homebrew-catalog) publishes a documented [Store API index](https://github.com/blackbearreloaded/ps5-homebrew-catalog/blob/main/docs/api.md) at https://homebrew.page/api/v1/index.json. Its compact apps array contains titleid and name. The inspected index contained 65 entries, generated 13 October 2026 from commit 5a338d3ab5b4479826c7edea53a39abba473d45d. The repository LICENSE is GPL version 3. Our independent parser consumes only those name/ID facts; no catalog code, descriptions, app binaries or assets are incorporated. The index is fetched at runtime and cached locally, not bundled in the release. Both online sources obey the same checkbox, cache limits and fallback policy. Disabling online names restores filtered internal metadata immediately while keeping selection/expansion state. Generic save-data labels are not treated as game titles; unresolved titles are empty.

Reviewed 13 October 2026: [KytyPS5 website README](https://github.com/KytyPS5/kytyps5.github.io/blob/main/README.md) identifies src/data/games.json as its deduplicated PS5 title database. [The JSON](https://github.com/KytyPS5/kytyps5.github.io/blob/main/src/data/games.json) contains name, titleId and allTitleIds; regional aliases include PPSA02184 = Chivalry 2, PPSA21567 = ASTRO BOT and PPSA01521 = Horizon Forbidden West. The app independently implements an HTTP fetch and parser for title facts only. It does not incorporate website or emulator code, art or compatibility text. The website code is GPL-2.0; it is not combined with this GPLv3 codebase. The database is fetched at runtime and cached locally, not bundled into release source/binaries. The URL, provenance and cache behavior are disclosed in the GUI, logs and README. Do not include a user's Cache directory in a release package.

ProsperoPatches was also reviewed via https://prosperopatches.com/PPSA01521. It exposes an HTML title page; a documented public bulk-title API was not established in this review. The structured KytyPS5 JSON is used instead of scraping one page per game. KytyPS5 requests fetch the same public file for everyone; console/user/save information is never added to that URL or request body. PS4 shadPS4 queries are described separately above and contain a missing CUSA ID. A seven-day cache, 8 MiB limit, twelve-second timeout and internal metadata fallback keep title lookups optional and bounded.
